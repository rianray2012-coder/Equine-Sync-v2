# API Versioning

## Purpose
Provide predictable API evolution.

## Current Version
**v1**

## Version Rules
Breaking changes require: a new API version, migration notes, documentation updates.

## Non-Breaking Changes (allowed)
- new endpoints
- optional fields
- performance improvements

## Breaking Changes (examples)
- removing fields
- renaming fields
- changing response structures
- changing permissions

## Deprecation Process
1. Mark deprecated
2. Document replacement
3. Notify consumers
4. Remove in future version
